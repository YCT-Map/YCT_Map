# Backlog Rules

The backlog exists to protect the current sprint from feature creep.

When a useful idea appears during implementation:

1. determine whether it is required for the current sprint;
2. if not required, add it to BACKLOG.md;
3. continue the approved sprint.

Backlog items should include:

- idea;
- reason;
- approximate priority;
- dependency;
- suggested release/version if known.

Do not implement backlog items without explicit approval.
