# Codex Reporting Standard

After significant work, report using this structure.

## Objective

What was the sprint/task intended to achieve?

## Implemented

What was actually changed?

## Files Changed

List meaningful files and why they changed.

## Tests

List:

- focused tests;
- regression tests;
- typecheck;
- builds;
- other gates.

Include actual pass/fail totals.

## Data / Migration Impact

State whether schema, migrations, or persistent data changed.

## Security Impact

State whether auth, permissions, secrets, storage, TLS, or sensitive data were affected.

## Decisions Made

Record any material decisions made during implementation.

## Unresolved Issues

List known remaining problems.

## Unexpected Events

Report failures, environment issues, tool limitations, or deviations.

## Git State

Report:

- branch;
- commit if created;
- worktree clean/dirty;
- push/merge/deploy status.

## Next Recommended Action

Give exactly the next logical step.

Never imply deployment, merge, or production mutation occurred unless it actually did.
